INTRODUCTION

Problem Background & Context

The Current Bottleneck

Traditional campus placement management is heavily reliant on static, unnormalized spreadsheets. During active placement drives, placement officers struggle to handle dynamic shifts in recruiter cutoffs, leading to manual errors and delays.

High manual overhead & error-prone

The "Black-Box" Rejection

Existing predictive tools merely return a binary "Pass" or "Fail" eligibility output. Ineligible students receive zero feedback on why they were disqualified and have no quantitative visibility into their skill deficiencies.

Zero actionable feedback for candidates

Our Proposed Solution

An intelligent, end-to-end software platform powered by a 3NF Relational Database (MySQL) and Machine Learning. Computes an objective Placement Readiness Index (0–100), checks live eligibility, and pinpoints exact numerical skill gaps.

Data-driven, transparent & dynamic

FEATURES: STUDENT MODULE (50% DELIVERED)

Phase 1 Implemented

Continuous Placement Readiness Score (0–100)

Evaluates multi-dimensional academic & coding metrics (CGPA, DSA assessment, LeetCode solved, project count, backlogs) through a trained Random Forest model. Categorizes candidates into Tier 1 Product, Tier 2 Core, or Mass Recruiter.

Instant Dynamic Drive Screening

Students can browse active placement drives (e.g., Google India, Microsoft IDC, Barclays). The system automatically evaluates student metrics against live SQL database cutoffs and labels them as ELIGIBLE, BORDERLINE, or INELIGIBLE.

Granular Numerical Skill-Gap Deficits

Eliminates blind rejections. Disqualified students receive an instant modal displaying exact shortfalls: "DSA score is 5.0 pts below cutoff", "CGPA deficit of 0.85", or "1 Active backlog violates company zero-backlog policy".

Profile Simulation & Real-Time Recalculation

Students can simulate improvements (e.g., solving 100 more LeetCode problems or clearing a backlog) to see their Readiness Index recalculate dynamically in real time before formal placement drives commence.

METHODOLOGY & SYSTEM ARCHITECTURE

4-Stage Iterative Layered Architecture
STAGE 1

3NF Database Modeling

Restructures placement data into 3NF normalized tables: users, students, companies, placement_drives, drive_criteria. Enforces primary/foreign keys to guarantee data integrity.

✓ 100% Implemented (MySQL)
STAGE 2

ML Predictive Engine

Feeds student feature vectors (CGPA, DSA score, LeetCode, backlogs, projects) into a trained Random Forest Regressor & Classifier. Generates calibrated Placement Readiness Index (0–100) & tier probabilities.

✓ 100% Implemented (Scikit-Learn)
STAGE 3

Dynamic Criteria Evaluation

Fetches live recruiter requirements from SQL. Simultaneously evaluates CGPA, backlogs, coding thresholds, and eligible branches. Branches output into: Eligible, Borderline, or Ineligible.

✓ 100% Implemented (Python SQL)
STAGE 4

Skill-Gap Diagnostic Engine

Calculates exact arithmetic deficits for failed checks. Pinpoints specific deficiencies (e.g. "Needs ~165 more LeetCode problems solved" or "Clear 1 active backlog") to guide candidate upskilling.

✓ 100% Implemented (Diagnostic Core)
